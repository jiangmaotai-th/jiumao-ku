# 九猫库测试规范（v1，测试工程师银酱，2026-10-10）

适用于 `jiangmaotai-th/jiumao-ku` 的功能与修复验收。开发流程、代码结构、上线与回滚以 `docs/ENGINEERING.md` 为准；玩法与规则以 `docs/DESIGN.md` 和 `docs/design/<功能>.md` 为准；美术资源与效果图以 `docs/ART.md` 为准。本规范只规定怎么测、怎么报、什么算过。公式、边界、文案和数值不在这里复述。

## 1. 流程

1. 每个功能或修复 PR，由银酱按**拍板后的设计稿**验收通过后才能合并上线（`docs/ENGINEERING.md` 第 1 节第 6 条）。验收依据是 `docs/design/<功能>.md` 里标为「已定」的内容（`docs/DESIGN.md` 第 1 节第 6 条、第 2 节）。「提案」和待定事项不作为通过条件。技术审核由猫汰做（`docs/ENGINEERING.md` 第 1 节第 5 条）。
2. 银酱按设计稿列出用例表（输入 → 期望）再验收。天宏在线上对照设计稿检查玩法（`docs/DESIGN.md` 第 1 节第 6 条）。画面是否符合效果图，由小瞳对照验收（`docs/ART.md` 第 1 节第 6 条）。
3. PR 描述写可执行的复现步骤和验收步骤（对应 `docs/ENGINEERING.md` 第 1 节第 4 条的「怎么验证」）。步骤从干净状态写起，不看代码也能走完。
4. 验收结果回帖在该 PR，或发到群里并注明 PR 链接。写明：通过或失败、证据（命令输出、截图、录屏）、未覆盖项。失败不合并。

## 2. 自动化测试

现有命令以 `package.json` 为准。语言切换的前置步骤另见 `README.md`「语言切换回归测试」和 `playwright.config.ts`。

1. **`npm run test:lang-switch`**：Playwright，使用自带 Chromium。先 `npm run build`，再 `npx playwright install chromium`，然后跑测试。默认测本地 preview（`http://127.0.0.1:4173`）。改测线上时设置 `BASE_URL`，例如 `BASE_URL=https://maotaiworks.com npm run test:lang-switch`。用例在 `e2e/lang-switch.spec.ts`，覆盖首页和竞技场。
2. **`npm run test:arena-rules`**：竞技场裁判规则。用 `docs/ENGINEERING.md` 第 5 节要求的 Node（v24.18.0）执行。期望值按 `docs/design/arena-battle.md` 里已定的公式手算（现有用例在 `tests/arena/rules.qa.ts`，检查脚本在 `tests/arena/rules.check.ts`）。公式正文以该设计稿为准，不在本规范复述。

要求：

- 规则或逻辑改动、以及 bug 修复，在**同一个 PR** 里补用例。修 bug 时先补一条能复现的用例，再改代码（`docs/ENGINEERING.md` 第 5 节）。
- 纯逻辑写成可单独调用的纯函数，不碰 DOM、动画、网络（`docs/ENGINEERING.md` 第 2 节）。日期、随机源和其他外部输入由调用方传入，用例里写死。
- 用例按该功能设计稿列出的边界来写：平局、缺数据、为 0、下限、上限、恰好等于阈值、取整发生在哪一步（`docs/DESIGN.md` 第 3 节）。贴边算进哪一侧以设计稿为准。缺这些边界不算测完。

`scripts/test-formats.mjs`、`scripts/test-markdown-web.mjs`、`scripts/test-pages-file.mjs` 未接入 `npm run`，不作为第 5 节的全量门禁。本次要用时，在 PR 里写明命令和结果。

## 3. 手工 / 端到端验收

1. 桌面和手机都走主路径。手机用模拟器；模拟器覆盖不到的见下面第 4 点。
2. 12 种语言做抽查。语言清单以 `docs/DESIGN.md` 第 7 节为准；文案走 i18n（`docs/ENGINEERING.md` 第 4 节）。`npm run test:lang-switch` 负责 12 语切换路径。手工至少看：默认语言、一种非中文、以及本次 diff 里改过的语言文案。缺数据、时效和来源按该功能设计稿处理，不用估计值填上（`docs/DESIGN.md` 第 4 节）。
3. 打开控制台，确认页面没有报错、没有卡死。
4. 模拟器测不到的项写进验收结果的「未覆盖」，并安排真机确认。例如 iPhone 真机 Safari 的自动播放、真实听感。真机确认之前，该项保持未覆盖。

## 4. 线上与共享数据

1. 优先对本地构建或测试端口测：`npm run build` 后 `npm run preview`，或 `docs/ENGINEERING.md` 第 6 节的本机端口加数据副本。
2. 必须碰线上时使用测试标记：写接口带 `test: true`（`docs/ENGINEERING.md` 第 6 节）；竞技场页面加 `?arena-test=1`（投票请求如何自动带标记见 `docs/design/arena-battle.md` 第 2.4.3 节）；需要昵称时固定用「测试-银酱」。先告知后端（猫汰）要写哪些接口、大约多少条。测完列出记录（时间、接口、标记或昵称、条数）交给后端清理。
3. 写接口有单 IP 和全局频率限制（`docs/ENGINEERING.md` 第 6 节）。分批测。被限制就停下，等窗口过去再继续。
4. 在本地构建或 preview 上测试时，会写入真实线上数据的请求先拦截（浏览器拦截或 mock），确认没有打到线上写接口再继续。

## 5. 回归

1. 上线前跑全部自动化测试：`npm run test:arena-rules`，以及按第 2 节准备好的 `npm run test:lang-switch`。
2. 修过的 bug 保留回归用例，之后相关改动继续跑。已修 bug 的用例留在仓库里。
3. 发布后对线上做冒烟，结果写入 `docs/ENGINEERING.md` 第 1 节第 7 条要求的「线上验证结果」：关键页面返回 200、语言切换可用、控制台无报错。冒烟只用读请求。

## 6. 缺陷报告

银酱不修改被测代码，也不改设计稿。

代码与已定设计稿不一致时，报给策划天宏。处理按 `docs/DESIGN.md` 第 2 节：以已拍板的设计稿为准，先由天宏确认稿是否正确。稿有误则先改设计稿（变更记录和群通知），再改代码；稿正确则由该改动的负责人在同一 PR 改代码（`docs/ENGINEERING.md` 第 1 节第 5 条）。不允许只改代码不改稿。

其他缺陷报给该改动的负责人，在同一 PR 上改。

每条缺陷包含：

1. **标题**：一句话，指出不符合设计稿的哪一条（写 `docs/design/<功能>.md` 的章节，不重写公式）。
2. **环境 / 提交**：本地或线上 URL、浏览器、桌面或手机、提交号。
3. **复现步骤**：从干净状态开始，可以重复。
4. **期望**：设计稿该节的规定（附章节，不把公式抄进缺陷）。
5. **实际**：当前结果。
6. **证据**：截图、录屏、控制台输出或命令输出。
7. **严重程度**：
   - 阻塞：主路径不符合设计稿，或可能写坏线上数据。验收不通过。
   - 高：主路径错误，存在明确绕过办法。
   - 中：次要路径、文案或单个语言。
   - 低：不影响操作的外观细节。

## 7. 测试资产

1. 用例脚本进仓库。逻辑用例放 `tests/`（现有 `tests/arena/`）。浏览器回归沿用 `e2e/`（现有 `e2e/lang-switch.spec.ts`）。
2. 共享电脑上的临时脚本、日志、抓包，用完即删。
3. 用例脚本在仓库内，期望值以对应设计稿为准。仓库外不另留一套用例；仓库里没有的步骤，不算回归。

## 8. 每个 PR 的测试检查清单

复制到 PR 描述或验收回帖，做完再勾。

- [ ] 验收依据写明 `docs/design/<功能>.md` 的稿名和版本，且只覆盖「已定」内容；用例表为输入 → 期望
- [ ] PR 描述含可执行的复现步骤和验收步骤
- [ ] 规则/逻辑改动或 bug 修复已在同 PR 补用例；日期和输入由外部传入；公式取自设计稿，不另写一套
- [ ] 用例覆盖设计稿中的边界：平局、缺数据、为 0、下限、上限、恰好等于阈值、取整（不涉及规则时注明）
- [ ] 若代码与设计稿不一致：已交给天宏，未自行改稿或改被测代码（没有不一致则注明）
- [ ] `npm run test:arena-rules` 通过（无关则注明跳过原因）
- [ ] 界面、文案或语言有改动时：已执行 `npm run build`、`npx playwright install chromium`，且 `npm run test:lang-switch` 通过
- [ ] 桌面和手机模拟器走过主路径；页面无报错
- [ ] 12 种语言已按第 3 节抽查
- [ ] 模拟器测不到的项已写明，并安排真机；未确认的保持未覆盖
- [ ] 在本地测。若碰了线上：已使用 `test: true`、`?arena-test=1` 或昵称「测试-银酱」，已告知后端，并附待清理记录
- [ ] 本地测试时，会写真实数据的请求已拦截
- [ ] 写接口分批发送，遇到频率限制已停下
- [ ] 验收回帖含：通过或失败、证据、未覆盖项
- [ ] 临时脚本和日志已删除；用例只在仓库内
