# 九猫库技术开发规范（v1，技术负责人猫汰，2026-10-10）

适用于 `jiangmaotai-th/jiumao-ku` 的所有工程改动（前端、后端、脚本、测试）。策划、美术规范由各自负责人另定。违反规范的 PR 不予合并。

## 1. 流程（需求 → 上线）
1. **需求定稿**：玩法/交互以策划设计稿为准，画面以美术方案为准；易秋拍板的事项写进设计稿后才开发。
2. **技术方案**：涉及新模块、接口、数据格式或改动超过约 200 行的，先在群里发简短方案（改哪些模块、接口/数据格式、风险、回滚方式），技术负责人批准后再写。
3. **分支**：从最新 `main` 拉分支，命名 `feat/…`、`fix/…`、`chore/…`、`test/…`、`docs/…`。禁止直接推 `main`。
4. **PR**：一个 PR 只做一件事。描述写清：改了什么、为什么、怎么验证、截图（有界面变化时）、是否影响线上数据。
5. **审核**：技术负责人审，必要时测试一起看。有修改意见在同一 PR 上改，不另开。
6. **测试验收**：测试按设计稿验收，通过后才能合并上线；改到线上行为的必须有测试结论。
7. **上线**：合并后从 `main` 构建；先在服务器备份 `dist` 到 `/var/backups/maotaiworks/deploy/`；`rsync` **永不加 `--delete`**；不得覆盖 `ai-daily`、`ai-skills`、`arena-data`、`arena-assets`。上线后在群里报：版本（提交号）、备份文件名、线上验证结果。
8. **回滚**：出问题先用上线前备份回滚，再查原因。

## 2. 代码结构与耦合
- **按职责分层**：规则/数据计算写成纯函数（如 `src/arena/rules.ts`），不碰 DOM、动画、网络；渲染层只负责画；数据层只负责读写。层与层之间通过类型明确的接口通信。
- **单一事实来源**：同一条规则、同一份配置、同一个映射只能有一份（例：选人逻辑只在 `scripts/daily/select_featured.py`；品牌映射只在 `arena-data` 的 `brand` 字段）。禁止前后端各写一份。
- **不跨模块伸手**：模块不得直接修改其他模块的内部状态或 DOM；需要协作时通过导出的函数或事件。
- **组件生命周期**：凡是注册了全局监听、定时器、订阅的组件，必须在 `destroy` 中全部移除；遍历监听者列表时先复制再遍历。
- **数据只放事实**：数据文件只存原始事实（分数、区间、来源、日期），派生值（伤害、档位等）由代码按规则计算，不写进数据。

## 3. 清理：不留废弃物
- 功能替换或下线时，**同一个 PR 内删除**旧代码、旧样式、旧接口、旧美术资源及其引用，不注释保留、不留 `old`/`bak`/`_副本` 文件。历史版本靠 git 找回。
- 不提交调试代码：`console.log`、调试全局变量、临时开关只允许在开发环境（`import.meta.env.DEV`）下存在。
- 美术资源删除前用全文搜索确认无引用；新增资源必须有引用。PR 描述列出增删的资源。
- 每个 PR 自查一遍有没有死代码、无用依赖、无用导出。

## 4. UI 开发
- **不做覆盖开发**：禁止用更高优先级的样式、`!important`、额外的遮盖层或绝对定位去“盖住”旧界面。要改就改原组件/原样式，改不动就重构，并删除旧实现。
- 样式按组件就近管理，类名带组件前缀，不写全局泛选择器。
- 可交互元素用语义化标签（`button`、`a`），有 `aria` 属性和键盘可用；文字一律走 i18n，12 种语言都要验证，不写死中文。
- 首页嵌入与独立页面共用同一组件，用参数区分模式，不复制一份。

## 5. 代码质量
- TypeScript 严格类型，`tsc --noEmit` 必须通过；不用 `any` 逃避类型（确需时写注释说明）。
- 新逻辑必须有测试：纯函数写单元测试，关键页面行为写端到端回归测试（现有：`npm run test:lang-switch`、`npm run test:arena-rules`）。修 bug 时先补一条能复现它的测试。
- 命名清楚，函数短小；注释写“为什么”，不写“做了什么”。
- 依赖：新增依赖要在 PR 说明理由；`package-lock.json` 用 Node `v24.18.0`、npm `11.16.0` 生成，不得夹带无关变动。

## 6. 后端与服务器
- 改服务代码前先备份原文件，先在本机端口用数据副本测通，再报技术负责人批准重启。
- 所有写接口必须有：类型严格校验（只收合法 JSON 类型）、频率限制（单 IP + 全局）、测试标记 `test: true`、输入清洗。IP 取 nginx 写入的 `X-Real-IP`。
- 服务器上的代码必须进仓库；线上不允许存在仓库里没有的改动。
- 密钥、账号、`.env`、`mail.json` 不进仓库；只放服务器或由易秋保管。
- 运行数据放在 `/var/lib/maotaiworks/`，纳入每日备份。

## 7. 提交与 PR 检查清单
- [ ] 分支基于最新 `main`，一个 PR 一件事
- [ ] `tsc --noEmit` 通过，相关测试全部通过，新逻辑有测试
- [ ] 无调试代码、无死代码、无废弃资源、无覆盖式样式
- [ ] 没有重复实现已有的规则/配置
- [ ] 全局监听/定时器在销毁时清理
- [ ] 文字走 i18n
- [ ] 不含密钥和运行时数据
- [ ] PR 描述含：改动、原因、验证方法、截图、上线影响
