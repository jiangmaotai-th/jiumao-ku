# 九猫库策划规范（v1，游戏主策划天宏，2026-10-10）

适用于 `jiangmaotai-th/jiumao-ku`（九猫库网站）的全部玩法、规则、数值和文案策划。工程侧以 `docs/ENGINEERING.md` 为准，美术侧以 `docs/ART.md` 为准；本规范只补充策划部分，三者冲突时按更严格的执行。

## 1. 流程（需求 → 验收）
**需求 → 策划案 → 易秋拍板 → 美术效果图 → 开发 → 验收**

1. **需求**：易秋或团队提出，写明目标、页面、优先级。
2. **策划案**：天宏写进 `docs/design/<功能>.md`，含玩法、规则、数值、边界情况、文案键、待定事项。
3. **易秋拍板**：需要决策的点逐条列出并给出建议，易秋确认后写入设计稿“已定”。
4. **美术效果图**：小瞳按定稿出效果图（`docs/ART.md` 第 1、6 节），天宏确认玩法表达。
5. **开发**：按 `docs/ENGINEERING.md` 流程，以设计稿为依据。
6. **验收**：银酱按设计稿出用例表验收；天宏在线上对照设计稿检查玩法。

**没有拍板的内容，不出资源、不写代码。** 未定事项可以出草图或技术方案，但不进入正式制作。

## 2. 设计稿是唯一依据
- 设计稿是玩法和规则的**单一事实来源**。规则一旦变化，**当天**更新设计稿：文首“变更记录”表新增一行（日期、谁定的、改了什么），并在群里通知改动要点。
- 设计稿与代码不一致时，**以已拍板的设计稿为准**：先确认设计稿是否正确；若设计稿有误，先改设计稿（走变更记录和群通知），再改代码。不允许只改代码不改稿。
- 讨论中的方案标“提案”，已拍板的标“已定”，两者不混写。

## 3. 数值与规则写法
- 公式写成可直接计算的形式，列明每个变量的含义、单位和来源字段。
- 必须写清：**边界情况**（缺数据、为 0、正好等于阈值、上下限）、**平局规则**、**取整方式**（向上 / 向下 / 四舍五入，以及发生在哪一步）、**封顶与下限**。
- 写法要让测试能直接据此列用例表：给出输入 → 期望输出的例子，至少覆盖正常值、边界值和平局。
- 计算示例和示例数据一律标注 **“示例数据”**，不得与真实数据混淆（与 `docs/ART.md` 第 6 节一致）。
- 派生值的计算规则写在设计稿，数据文件只存事实（`docs/ENGINEERING.md` 第 2 节）。

## 4. 真实数据
- 用到真实数据的功能（如竞技场跑分、鹈鹕图），每条数据必须带**来源链接**和**日期**，并在画面或说明里可查。
- **不编造数据**：查不到、过期或双方缺数据时按设计稿的缺数据规则处理（如“无共同数据”），不用估计值或占位值顶上线。
- 数据时效、来源范围等规则写进设计稿（例：竞技场只用 6 个月内的跑分）。

## 5. 待定事项
- 每份设计稿末尾有“待定事项”表：事项、建议方案、负责人（谁拍板 / 谁跟进）、状态（待定 / 已定 / 已撤销）、日期。
- 已定的事项同步写回正文并记入变更记录，表里标“已定”。

## 6. 文档位置
- 设计稿放 `docs/design/<功能>.md`，文件名小写英文 + 连字符（如 `arena-battle.md`）。
- **不留** `_old`、`_v2`、副本、final 等文件，历史靠 git；版本号写在文首状态行里。
- 只放九猫库网站的策划文档。其他项目（如套大鹅）的文档不进本仓库。

## 7. 多语言
- 所有玩家可见的文字（按钮、提示、招式名、结算文案、说明行等）必须使用文案键，设计稿里列出键名和中文原文，不写死中文。
- 必须覆盖 12 种语言：zh-CN、zh-TW、en、ja、ko、fr、de、es、hi、th、ru、pt。新功能上线时 12 种语言齐全；暂不支持的语言要写明回退规则。
- 设计时考虑长文本（德语、俄语等）和泰语、印地语字体回退，给出字数或宽度上限。
- 图片中的文字按 `docs/ART.md` 的按语言出图规则处理（如 `dock-${loc}.png` 拼名加载及兜底）。

## 8. 策划 PR 检查清单
- [ ] 改动已经易秋拍板（附群里确认时间），未定内容标“提案”
- [ ] 变更记录已加一行，群里已通知
- [ ] 公式、边界、平局、取整、上下限写全，测试可直接列用例
- [ ] 示例数据已标注“示例数据”
- [ ] 真实数据有来源和日期，无编造
- [ ] 文末待定事项表已更新（负责人、状态）
- [ ] 玩家可见文字都有文案键，12 种语言或回退规则已写明
- [ ] 文件在 `docs/design/` 下，命名合规，无 `_old` / `_v2` / 副本
- [ ] 不含其他项目的文档
- [ ] 与 `docs/ENGINEERING.md`、`docs/ART.md` 无冲突
