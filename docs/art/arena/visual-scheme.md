## 0. 现状盘点（src/arena/）
- 像素风，逻辑画布 **384×216**（`scenes.ts` SW/SH），整数倍放大，`imageSmoothingEnabled=false`。
- 字体：Fusion Pixel 12px（`/fonts/arena-pixel.woff2`），泰语、印地语回退到 Noto Sans Thai / Devanagari（`font.ts`）。
- 主色（按代码里出现的频次）：底色 `#0a0716 / #120a1e / #14121c`，强调 `#ffd23f`，青 `#7ef0ff`，绿 HP `#6cd84c`，粉红 `#ff5a7a / #ff4f8b`，橙 `#f27c2c`，蓝 `#86b8ff / #5ca2ff`，紫 `#3b2a72`。

> **角色 = 现有竞技场角色，不改。** 易秋要求：v2 的对战角色全部沿用当前版本 `src/arena/fighters.ts` 里的 21 个角色（knight、dragon、mage、mech、whale、scholar、rabbit、fox，以及各厂商形象和 mystery 染色），精灵表 `public/arena-sprites/<avatar>.png`（12 帧 × 68px：idle0-2、charge、attack0-2、hurt、block、down、win、taunt），造型、配色、动作帧都不重画，模型到角色的对应关系也照旧。v2 只用现有的帧来配新演出（攻击回合用 attack、格挡用 block、K.O. 后用 down 等）。效果图里的角色已经换成真实精灵（示例用 knight 对 mage），早先版本里的方块小人只是占位。

## 1. 总体风格
- 夜市街机风：深紫夜空 + 像素地台，左方青色系（`#7ef0ff`），右方粉色系（`#ff4f8b`）。阵营色固定，不跟模型品牌色走，避免误导，也省掉配色授权问题。
- 真实数字是主角：数字用像素字 2 倍高、描 1px 深色边，滚动停住后 ≥1 秒（第 7 节要求）。
- 特效只放大“分差”，不能改数字本身；分差和特效档位由前端 `rules.ts` 按原始分数统一计算。

### 2.3 角色尺寸与清晰度
- 现有精灵原生分辨率：每帧 68×68，角色实际像素约 38–50 宽、36–50 高（精灵表 `public/arena-sprites/*.png`，12 帧横排）。
- 旧效果图按 3 倍显示（204×204），和现有 384×216 画布里的大小相当，看起来偏小。
- **v2 定为 6 倍整数缩放：** 每帧在 1280×720 下显示为 408×408，角色本体约 230–300px 高；在 384×216 逻辑画布里相当于 2 倍（136×136 逻辑像素一帧）。
- 只用整数倍 + 最近邻（canvas `imageSmoothingEnabled=false`，CSS `image-rendering: pixelated`），不做任何平滑。
- 加 1 个原生像素宽的深色描边（`#0a0716`，屏幕上 3px 的四向投影）和一条脚下投影，压在夜空和特效上也分得清。K.O. 灰显时描边保留。
- 布局随之调整：图表层收窄到 x 380–900，夹在两个角色中间；伤害数字、BLOCK、计分板都放在中间列，不压角色。
- **要不要重画高清版：** 不需要。这是像素风，68px 帧按整数倍放大，边缘依然锐利，6 倍效果见新效果图。只有想要 8 倍以上或做全屏特写时才值得重画；本方案不重画。

### 2.4 宽度规则（旺财 2026-10-10 提）
- 面板、窄栏、条、画框、按钮等**布局宽度一律按战斗容器（`.arena` 画面框）宽度的比例**标注（百分比或分数），必要时加 px 上下限（`clamp(min, 比例, max)`）。文中括号里的 px 只是 1280 宽时的参考值。
- **禁止用视口单位（`vw`/`vh`）定宽。** 教训：大鹅挑战模式卡片写成 `min(420px, 92vw)`，按浏览器窗口算，游戏框只有 370px 时右侧被裁（dongbei-goose issue #9）。实现用容器百分比或容器查询单位（`cqw`）。
- 例外：精灵、像素素材保持整数倍缩放（6 倍等），不按百分比拉伸；字号、边框、投影仍用 px。

### 3.1 分差档位（`g`）
| 档 | g | 粒子 | 震屏 | 伤害字 |
|---|---|---|---|---|
| 擦伤 | <0.15 | 12 粒 | 无 | 白色 24px |
| 重击 | 0.15–0.35 | 30 粒 | 2px 0.2s | 粉红 32px |
| 暴击 | >0.35 或 crit | 60 粒 + 交汇点白闪 | 4px 0.3s | 粉红 48px + “CRIT!” |
### 3.2 格挡（0 伤害）
- 两边置信区间重叠（或没有 CI 时 g<0.05）就是格挡：交汇点出现黄色虚线框的竖条纹“火花屏障”，宽度=两侧 CI 之和，双方能量条撞上去弹回，都用 `block` 动作帧。
- 中央大字 “BLOCK”（`#ffd23f`），两边头上都显示 “0 伤害”。**格挡不扣血**，不再有“2 点震伤”。
- 如果一整场全是格挡，HP 就一直是 100:100，按实际情况判平局，画面不加任何“凑戏”演出。
### 3.3 不做残血保护
- 已取消残血保护：伤害照公式扣，HP 归零就 K.O.。原来的“护盾吸收”护盾碎片素材删掉。
### 3.4 缺数据回合
- 单个榜单缺数据：不出招、不上场，画面上不出现空回合。结算页列“未开打：xx 榜（某方无数据）”。
- **整个类别都没有共同数据：** 回合进度条在该类别的位置保留一个灰色格，标“无共同数据”；不占播放时间，也不算回合（不计入回合号 N 和 46 秒预算）。
### 3.5 单回合时间轴（可从 6.5 秒拉长到 9 秒）
每个计分回合时长 = max(6.5, 46 / 计分回合数) 秒，最多 9 秒。动画按“弹性段”设计，多出来的时间只分给能伸缩的段，节奏不会变拖：
| 段 | 6.5s 时 | 9s 时 | 伸缩方式 |
|---|---|---|---|
| 招式横幅 | 1.0 | 1.2 | 基本固定，只多停一点 |
| 蓄力 | 1.5 | 1.8 | 固定动作循环多播半圈 |
| 图表生长 + 数字滚动 | 2.0 | 3.0 | **主要伸缩段**：条长得更慢，数字按 ease-out 滚到真实值 |
| 命中/格挡 | 1.0 | 1.0 | 固定，打击感不能拖 |
| 结果停留 | 1.0 | 2.0 | **伸缩段**：真实分数和来源句多停，适合阅读 |
- 拉长时比例：多出的时间 40% 给图表生长、40% 给结果停留、20% 给横幅和蓄力；打击段永远 1 秒。
- 整场时长 = 开场 6s + 计分回合合计（≥46s）+ 鹈鹕 6.5s（有图时）+ 结算 8s，所以整场永远 ≥60 秒；只靠拉长回合凑够，不加假回合。
- 数据里只放原始事实（分数、CI、来源、日期）；分差、档位、回合时长都由前端在 `rules.ts` 里算，再按上表比例分配各段时长，不需要两套动画。

## 4. HP 条与分段（固定出场顺序）
- HP 条沿用现有样式：白框、绿条、延迟扣血用粉红块（lagHp），HP ≤30 闪烁。**HP 为 0 时条内不留任何颜色**（之前 K.O. 图里残留红块是 bug，已修）。
- 每场出场顺序固定：**人类盲测 → 知识推理 → 数学 → 编程 → 综合指数 → 鹈鹕展示（最后，不计分）**。不再有“三幕悬念”节奏，分段就是按类别分组。
- HUD 中间的小框显示当前类别名 + 回合号 + 回合进度条（每格一回合，类别之间留 4px 间隔）。小框有深色底和紫边，压在特效光柱上也看得清。
| 分段 | 背景点缀 | 横幅底色 |
|---|---|---|
| 人类盲测 | 背景人群剪影 | 紫→蓝 |
| 知识推理 | 远处书架灯笼 | 蓝→青 |
| 数学 | 地面浮现淡法阵 | 紫→粉 |
| 编程 | 背景代码雨 | 橙→粉 |
| 综合指数 | 天空泛金 | 金→橙 |
| 鹈鹕展示 | 降饱和，聚光两张图 | 绿→蓝 |
- 背景点缀只是分组标识，强度不随“剧情”变化；伤害强弱只由分差档位（3.1）决定。

### 4.1 K.O. 之后：「已 K.O.，追加数据」
- **胜负规则：** 谁先被 K.O. 谁输；没人 K.O. 时 HP 多的赢；HP 相同为平局。
- **触发：** HP 归零 → 播 K.O. 演出（金色 K.O.!、败方 `down` 帧，2 秒，包含在该回合时长内），然后进入追加状态，剩下的回合照常逐个打完。
- **常驻标识：** 顶条变蓝色“已 K.O.，追加数据 · ROUND x / N”；背景加淡蓝斜纹；败方 HP 条空框 + 小字“K.O. @ 第 n 回合”。
- **败方灰显（定稿参数）：** 一直保持 `down` 帧倒地；先完全去色（grayscale 100%），再叠一层 `#5a6478`、35% 不透明度（只盖在角色像素上），整体不透明度 70%。
- **回合照常对撞：** 横幅、能量条、真实数字、来源都照旧，副标题加“追加数据（不计伤害）”，败方的条降饱和。
- **数字：** 不扣血，只显示“回合胜 +1 A/B（不扣血）”或“BLOCK · 平”。
- **回合胜场计分板：** 黄框常驻“回合胜场 A x : B y · 格挡 z”，每回合结束跳数字。
- **首页预览：** 不展示追加状态。

### 4.2 结算画面（固定 8 秒）
- **主标题**（金色大字）三种：
  - `Model A K.O. 胜`（有人被 K.O.）
  - `Model A 胜`（打满全部回合，HP 多者胜；副标题加“HP 71 : 48”）
  - `平局`（HP 相同）
- **第二行：** `回合胜场 X : Y · 格挡 Z · 鹈鹕展示 1`。
- **备注行**（浅黄色）：只要赢家的回合胜场 < 输家，就显示“对方赢的项目更多，但这边赢下的项目分差更大”，K.O. 胜和 HP 判定胜都适用；K.O. 之后的追加回合也计入回合胜场。平局永远不显示。例：`Model A 胜 · 回合胜场 4 : 5` + 备注行。
- **中间战报：** 按 6 个分段列出每项归谁（A / B / 平），K.O. 那回合标“（K.O.）”，K.O. 后的回合标“（追加）”，最后一行“查看全部 N 条来源与日期”。
- **角色：** 赢家 `win` 帧，输家 `down` + 灰显（同 4.1）；平局时双方都用 `idle`。

## 5. 来源 + 日期标签（常驻）
- 位置：画面右下角，距边 1.25% 容器宽（clamp 8–16px），最大宽度 40% 容器宽，青色 2px 边框、半透明深底，格式 `来源 域名 · YYYY-MM-DD ▸`。
- 整场常驻，随回合切换内容；可点击打开原链接（新标签页）。

- 宽度不够时只截域名（不截日期），完整 URL 放 tooltip 和结算页列表。
- 首页预览同样放在右下角，字号 11px，日期写 MM-DD。


## 6. 鹈鹕展示回合（每场最后，无伤害）
- 固定放在所有计分回合之后、结算之前，时长固定 6.5 秒，不计入 46 秒的回合时长预算。
- 顶条“ROUND N / N · 最终 · 鹈鹕投票（不计伤害）”，HP 条冻结（K.O. 了的也保持 0）。
- 两张**真实** SVG 并排，各 360×252 的浅黄画框，投票前下方只写“图 A / 图 B”（匿名盲投，见 6.1）；一只像素鹈鹕骑车横穿作为转场。
- 不计分，改为观众匿名投票（见 6.1）；来源标签和原文链接投票或跳过后才出现。
- SVG 用 `<img>` 加载自己服务器上的副本，不内联；没有图就整段跳过，直接进结算。

## 6.1 鹈鹕投票界面（最后一回合，不影响胜负）
效果图：`keyframe-pelican.png`（投票前）、`keyframe-pelican-voted.png`（已投票、≥20 票）、`keyframe-pelican-few.png`（已投票、<20 票）、`keyframe-pelican-skipped.png`（跳过、投票关闭）、`keyframe-result.png`（结算页小入口）。全部示例数据，鹈鹕图是标注“占位图”的示意，上线放真实 SVG。
### 匿名盲投规则（天宏 2026-10-10 定）
- 投票前两张图只标“图 A”“图 B”，**不出现任何模型名**；A/B 的左右位置**每场随机**，不跟角色站位走（效果图里看不出随机，以本条为准）。
- 图片地址、文件名、`alt`、`aria-label`、页面数据和投票请求里都不带模型名：每张图用服务端生成的不透明编号（如 `p_7f3a`），投票传这个编号，服务端记录对应模型。
- 原文链接、署名（右下来源标签）**只在投票后或跳过后**显示，跟作者一起揭晓；揭晓后标签变为“图 A · 模型名”。
- 按钮下方一行 16px 小字：“匿名盲投，投完揭晓作者 · 也可直接跳过”。
- **跳过即关闭投票：** 用户跳过（或调用揭晓接口）后，本场对该 IP 记为“已揭晓”，两个按钮变为不可用“🔒 投票已关闭”，下方灰框“你已跳过，本场投票已关闭 / 作者与原文已揭晓 · 不能再投票”；服务端同样拒绝后续投票。
- 顶部 HUD 仍显示对战双方名字（观众本来就知道是谁在打），匿名只隐藏“哪张图是谁画的”。
- **画面上部：** 标题横幅“哪张鹈鹕骑自行车画得更好？”（绿→蓝渐变，30px，深色描边 + 6px 投影）；揭晓后下面加一行原文链接（青色下划线，16px）。**不做倒计时**，玩家不投也不会自动跳过（“跳过演出”照常可用）。
- **两张图：** 并排，每张画框宽 25% 容器宽（clamp 240–320px，1280 宽时 320），高按 10:7 比例（1280 宽时 224），深色 4px 边 + 4px 投影，间距 6.25% 容器宽（1280 宽时 80px）；下面写“图 A / 图 B”（左青右粉），揭晓后为“图 A · Model X”。
- **按钮：** 每张图下方一个“这张更好”，全部用 HTML 叠层（`<button>`，可点击、可键盘操作，`aria-label="投给图 A"`，不带模型名）。
### 按钮尺寸与状态（桌面：宽同画框 25% 容器宽，clamp 240–320px；高 52px；字号 22px）
| 状态 | 样式 |
|---|---|
| 默认 default | 深底 `#14121c`，4px 边框和文字用阵营色（左 `#7ef0ff` / 右 `#ff4f8b`），4px 黑色投影，前面加“▶” |
| 悬停 hover / 键盘焦点 | 底色换成阵营色 20% 透明，投影加到 6px，焦点额外 3px 白色外框 |

| 不可用 disabled | 另一侧（跳过后两侧都是，文字改“🔒 投票已关闭”）：底色 `#241640`、虚线边框 `#3b2a72`、灰字 `#6a6080`，`aria-disabled="true"`；请求发送中两侧都临时进入这个状态 |
### 投票后
- **≥20 票：** 下方显示“图 A 132 票 · 58%”和“42% · 96 票 图 B”（左右对齐），一条 22px 高、宽 = 两张画框外沿之间（约 56.25% 容器宽）的双色百分比条（左青右粉，白框），再一行“共 228 票 · 按 IP 计票，仅供参考，不影响胜负”。
- **<20 票：** 不显示票数和比例，只显示一个蓝框“已投票，票数较少暂不公布比例 · 共 12 票”，小字“满 20 票后显示比例 · 按 IP 计票，仅供参考，不影响胜负”。
- 投票前不显示任何票数，避免跟风。
### 结算页小入口
- 战报下方一个 2 行小卡片（绿框，宽 31.25% 容器宽，clamp 280–400px，高约 60px）：“鹈鹕盲投：哪张画得更好？”+ 两个小按钮“A 这张更好 / B 这张更好”（各占卡片内宽约 47%，高 28px，字号 15px）。已投票时换成一行“已投 A · 共 N 票”（≥20 票时加百分比）。

## 7. 色彩与字体规则
- 左方 `#7ef0ff` / 右方 `#ff4f8b`；伤害 `#ff5a7a`；格挡、KO、强调 `#ffd23f`；来源 `#7ef0ff`；底色 `#0a0716 → #14121c`。
- 文字一律像素字，最小 8px（逻辑像素），数字最小 16px。所有文字描 1px `#14121c` 边，保证在特效上可读。
- 青和粉之外加形状区分（左方条带竖分段、右方实心），照顾色弱玩家。

## 8. 12 种语言的文本长度
- 招式横幅：可用宽度 300 逻辑像素。先按单行排，超宽就缩到 10px，再超就拆两行（按 `·` 断开），仍超才省略号；德语、俄语、法语、葡语、印地语最容易超。
- 中日韩字按 12px 方块算，拉丁字母约 6px，泰语、印地语回退字体行高另加 2px。
- 回合号、BLOCK、K.O.、CRIT 是固定美术字，不翻译（街机惯例）；“回合胜”“追加数据”“仅展示”等走 i18n。
- 数字、%、Elo 统一用阿拉伯数字和半角符号，不随语言变。

## 10. 性能
- 画布保持 384×216，再用 CSS 整数倍放大，填充率很低。
- 粒子上限 60（暴击档），首页预览上限 30；对象池复用，不在帧循环里分配内存。
- 精灵表合成 1–2 张图集，首屏额外资源目标 ≤150KB。
- 页面不在视口或标签页隐藏时暂停动画（`IntersectionObserver` + `visibilitychange`）。
- 文字测宽结果按语言缓存（现有 `engine.ts` 有省略号函数，可复用）。
- “跳过演出”直接画结算帧，不用快进。
