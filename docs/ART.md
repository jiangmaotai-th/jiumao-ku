# 九猫库美术规范（v1，美术负责人小瞳，2026-10-10）

适用于 `jiangmaotai-th/jiumao-ku` 的全部美术工作：插画、像素角色、UI 视觉、图标、海报、社媒图。工程侧以 `docs/ENGINEERING.md` 为准，本规范只补充美术部分，两者冲突时按更严格的执行。

## 1. 流程（需求 → 上线）
1. **需求**：策划设计稿（天宏）或易秋提出，写明用途、页面、尺寸、截止时间。
2. **风格参考**：先给 2–3 张参考或色块草图，确认方向后再细化。沿用现有风格的直接引用本规范第 5 节。
3. **效果图评审**：出关键帧效果图和视觉方案（如 `visual-scheme.md`），在群里发给天宏确认玩法表达、易秋确认画面。**没确认不进入正式制作。**
4. **资源制作**：按第 3、4 节的格式、尺寸、命名出图，压缩后做目测对比。
5. **PR**：分支 `feat/art-…` 或 `chore/art-…`，一个 PR 只做一组相关资源。描述列出：新增/替换/删除的文件、用在哪、压缩前后体积、截图。
6. **审核与实现**：猫汰审 PR；旺财按效果图和 token 实现，接入时有问题回到效果图上改，不在代码里临时调色。上线后小瞳在线上对照效果图验收。

## 2. 目录与命名
现有目录，新资源放进对应位置，不新建平行目录：

| 目录 | 内容 |
|---|---|
| `public/arena-sprites/` | 竞技场角色精灵图（每个角色一张序列帧图） |
| `public/fonts/` | 字体文件 + 对应授权（`*-OFL.txt` 必须同目录） |
| `public/goose/`、`public/tank/`（`ui/` `scenes/` `decor/` `fish/` `packs/`） | 各游戏/应用的资源，按模块分子目录 |
| `public/covers/` | 应用卡片封面 |
| `public/image/` | 站点通用图（横幅、徽章） |
| `public/generated-assets/` | 工具生成的序列帧图 + `*.frames.json` 帧数据，二者同名成对 |

- 文件名：小写英文 + 连字符，`模块-内容[-状态].ext`，如 `catch-burst.png`、`chest-rare.png`。不用中文、空格、版本号、日期。
- **禁止** `_old`、`_bak`、`_v2`、`副本`、`final` 等后缀；改版直接覆盖同名文件或改名并删除旧文件，历史靠 git。
- 带模型品牌的角色可用品牌名（`arena-sprites/meta.png`），但**鹈鹕投票图除外**（见第 7 节）。

## 3. 格式与尺寸
- **像素画**：按原生分辨率绘制（竞技场画布 384×216 逻辑像素），只允许**整数倍**放大，渲染用最近邻（CSS `image-rendering: pixelated`，canvas 关闭 `imageSmoothingEnabled`）。不交付已放大的像素图。
- **PNG**：像素画、需要精确透明边缘的图；用 pngquant/oxipng 压缩，像素画只能无损或限定调色板。
- **WebP**：照片、插画、大背景、序列帧大图；质量从 80 起试，透明图注意边缘。
- **JPG**：仅封面类无透明的照片图。
- **SVG**：图标、Logo、鹈鹕投票图等矢量内容；去掉编辑器元数据、内嵌位图和外链。
- **压缩必须目测**：每次压缩出前后对比图（同屏 1×、2×），关键资源附 SSIM；PR 里写体积变化。看出色带、边缘脏点就退回更高质量。
- 单张资源一般不超过 300 KB，超过在 PR 说明理由。

## 4. 源文件
- 源文件（`.aseprite`、`.blend`、`.psd`、`.fig` 导出等）**不进站点 `public/`**，不随构建上线。
- 需要长期维护的源文件放仓库 `art-src/<模块>/`，与导出文件同名（`art-src/arena/mage.aseprite` → `public/arena-sprites/mage.png`）；超过 10 MB 的不进仓库，放易秋指定的网盘并在 PR 里写位置。
- 导出参数（缩放、调色板、帧率）写进同目录 `README.md`，保证别人能重新导出。

## 5. 色板与字体（竞技场 / 夜市街机风）
- 底色 `#0a0716` → `#120a1e` → `#14121c`；暗紫 `#3b2a72`、`#241640`
- 左方阵营青 `#7ef0ff`，右方阵营粉 `#ff4f8b`（阵营色固定，不跟品牌色）
- 强调/格挡/KO `#ffd23f`；伤害 `#ff5a7a`；HP 绿 `#6cd84c`；橙 `#f27c2c`；蓝 `#86b8ff` / `#5ca2ff`；禁用灰字 `#6a6080`
- 字体：Fusion Pixel 12px（`/fonts/arena-pixel.woff2`），泰语、印地语回退 Noto Sans Thai / Devanagari。最小字号 8px，数字最小 16px，文字描 1px `#14121c` 边。
- 新颜色先加进视觉方案和 token，再使用；不在组件里写散落的色值。其他模块的色板在各自视觉方案里定义，同样遵守此规则。

## 6. 效果图与交付物的区别
- 效果图只用于评审，**不是上线资源**，不放进 `public/`、不被代码引用。效果图和视觉方案放 `docs/art/<模块>/`（或评审期放共享电脑，定稿后进仓库）。
- 效果图里的占位内容必须标 **“占位图”**，假数据标 **“示例数据”**，避免被当成真实素材或真实结果。
- 定稿后旧版效果图直接覆盖或删除，不留 `_old` 版本。

## 7. 删除与替换
- 资源替换或功能下线时，**同一个 PR 内删除**旧资源及其所有引用（`rg` 全文搜文件名确认），PR 描述列出删除清单。
- 新增资源必须在同一 PR 中有引用；没有引用的资源不合并。

## 8. UI 美术交付方式（不做覆盖开发）
- UI 视觉以**组件 + token** 交付：颜色、字号、边框、阴影、间距写成 token 表，按钮等交付全部状态（默认、悬停、按下、选中、禁用）。
- 不交付“盖在旧界面上”的整张贴图、遮罩或装饰层；要改旧界面就改原组件的样式和资源，并删除旧资源。
- 首页嵌入和独立页面用同一套资源，不复制一份。

## 9. 无障碍
- 文字与背景对比度 ≥ 4.5:1（大字、像素数字 ≥ 3:1）；阵营不能只靠颜色区分，配合左右位置、文字或图标。
- 有信息的图片必须有 `alt`（走 i18n）；纯装饰图 `alt=""`。
- **鹈鹕匿名投票**：投票前图片文件名、URL、`alt`、页面数据中**不得出现模型名或品牌**，只用“图 A / 图 B”和服务端不透明编号；作者、原文链接投完或跳过后才显示（规则以策划稿第 2.4 节为准）。
- 动效提供 `prefers-reduced-motion` 下的简化版本；闪烁不超过每秒 3 次。

## 10. 美术 PR 检查清单
- [ ] 效果图已经天宏 / 易秋确认（附群里确认的时间）
- [ ] 文件放在第 2 节对应目录，命名合规，无 `_old` / `_v2` / 副本
- [ ] 像素图为原生尺寸、整数倍缩放、最近邻渲染
- [ ] 已压缩并目测对比，PR 写明体积变化
- [ ] 新资源都有引用；被替换的旧资源和引用已在本 PR 删除
- [ ] 无效果图、占位图、源文件混入 `public/`
- [ ] 颜色、字体只用色板和 token
- [ ] 对比度、`alt`、鹈鹕匿名规则已检查
- [ ] 字体等第三方素材的授权文件随附
